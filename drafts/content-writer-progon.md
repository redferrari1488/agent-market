# Прогон content-writer (обед 29.05)

Цель: своими глазами увидеть качество постов и approve-flow. Локально, прод не трогаем.

## 0. Подготовка в Telegram (5 мин)
1. **@BotFather** → `/newbot` → имя → скопируй **токен**.
2. **Напиши своему боту `/start` в личке** — иначе бот не сможет тебе писать (TG запрещает ботам писать первыми). Частый затык, не пропусти.
3. Создай тестовый **канал**, добавь бота в **администраторы** с правом публиковать.
4. **@userinfobot** → `/start` → запомни свой numeric **id** (это `OWNER_CHAT_ID`).

## 1. Сборка
```
cd agents-src
docker build -f content-writer/Dockerfile -t content-writer .
cd content-writer
cp .env.example .env
```

## 2. Заполнить .env
- `TELEGRAM_BOT_TOKEN` — токен из BotFather
- `CHANNEL_ID` — `@твой_канал`
- `OWNER_CHAT_ID` — твой id из userinfobot
- `TOPIC`, `CONTENT_PILLARS` — ниша и рубрики
- `EXAMPLES` — **2-3 реальных поста** (главный рычаг качества; в кавычках, многострочно)
- `OPENAI_API_KEY` — твой OpenRouter-ключ
- `POST_INTERVAL_HOURS=6` (на следующие; первый черновик придёт сразу при старте)

## 3. Запуск
```
docker compose up --build
```
В логах: `Content writer started` → `Draft prepared`. В личку прилетит черновик с кнопками.

## 4. Что проверить
- [ ] черновик пришёл в ЛС (не в канал)
- [ ] **[Опубликовать]** → пост появился в канале
- [ ] **реплай своим текстом** на черновик → в канал ушёл твой вариант
- [ ] **[Переписать]** → другой вариант; **[Пропустить]** → ничего
- [ ] **качество**: прогони раз с заполненным `EXAMPLES`, раз с пустым (`docker compose down` → правь .env → `up`) — сравни. Стало похоже на канал, а не на GPT?

## 5. Стоп
```
docker compose down
```

## Если затык — пиши мне «прогон content-writer» + что не так
- бот молчит → не написал боту `/start`, или `OWNER_CHAT_ID` неверный
- не постит в канал → бот не админ канала / нет права публиковать
- упал на старте → смотри лог, скинь мне последние строки

После «качество ок» → я обновлю setup_schema в проде, и агент готов к продаже.
