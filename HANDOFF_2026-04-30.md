### `64cbf0a` — fix(yookassa): webhook idempotency-check no longer treats first webhook as retry
**Найденный баг:** `/api/checkout` записывал `provider_payment_id` сразу после создания платежа в ЮКассе (до webhook'a). Когда webhook прилетал с тем же `payment_id`, idempotency-check думал «это ретрай» и не выставлял `expires_at`.

Симптом: подписка зависала в `pending_setup` навсегда без `expires_at`, никогда не активировалась.

Фикс:
- `/api/checkout/route.ts`: убрана ранняя запись `provider_payment_id`. Связь webhook ↔ subscription идёт через `metadata.subscription_id`, ID платежа выставляет webhook сам.
- `/api/webhooks/yookassa/route.ts`: idempotency-check переписан. Webhook = ретрай только если `provider_payment_id` совпал И (`one_time` ИЛИ `expires_at != null`). Это исключает ложное срабатывание на первом webhook'е и сохраняет защиту от двойных ретраев.

### `7864764` — fix(header): seller dropdown links depend on role
- `src/components/layout/Header.tsx`: ссылки в выпадашке зависят от `user.role`
- Не-продавцы видят только «Стать продавцом», продавцы/админы видят «Панель продавца» + «Создать агента»
- Раньше всем показывалось обе ссылки → buyer'ы при клике на «Создать агента» получали silent redirect на форму заявки

## 4. Технические долги (не блокеры)

### A. `PAYMENTS_ALLOW_CRYPTOMUS` не пробрасывается в контейнер app

В `docker-compose.yml`, секция `environment` контейнера `app`, нет переменной `PAYMENTS_ALLOW_CRYPTOMUS`. Сейчас не страшно (у Cryptomus нет ключей в env, провайдер всё равно `null`), но как только появятся `CRYPTOMUS_*` — флаг не сработает.

Фикс: добавить строчку в `docker-compose.yml`:
```yaml
PAYMENTS_ALLOW_CRYPTOMUS: ${PAYMENTS_ALLOW_CRYPTOMUS:-}
```

### B. Один реальный тест боевой картой не сделан

После переключения на live в этой сессии живых платежей не было. Технически оно должно работать (тестовый стенд работает идентично), но первый реальный платёж = смок-тест, который ещё не пройден. Желательно один раз купить → рефанд из кабинета.

### C. Проверка `cron/yookassa-recurring`

Месячные авто-списания через `payment_method_id` теоретически работают, но не тестировались на тестовом стенде с реальной подпиской на месяц. Cron гоняется раз в сутки. Будет первый кейс через ~30 дней после первой подписки.

### D. `compute_class` дороже чем должен быть для дешёвых агентов

Класс L (1690₽/мес) накручен поверх цены агента. У `news-digest-bot` цена 1500₽ + L = total 3190₽/мес. Покупателю кажется дороговато за «новостной дайджест». Стоит пересмотреть compute класс агентов: которым реально не нужен L — переставить на S.

### E. Resend (email-уведомления)

Внешний блокер с 2026-04-21. Без него:
- Юзер не получает email после одобрения заявки продавца
- Модератор не получает email о новой заявке (ловит только ручным обновлением `/admin/applications`)

Для MVP приемлемо, для post-Phase-0 — настроить.

## 5. Что можно сделать через Claude Design (раз есть лимит)

Раз тратить дизайн-лимит, имеет смысл делать то, что **сложно скопипастить из shadcn** и где визуал реально влияет на конверсию. Топ-кандидаты по убыванию ROI:

### Высокий ROI

1. **Hero-секция главной страницы** — сейчас текстовая, без иллюстрации. Сделать визуальный hero с превью каталога + явный CTA «Купить агента». Конверсионная зона #1 для приходящего трафика.

2. **Иконки/обложки 6 founder-агентов** — сейчас, скорее всего, generic placeholder'ы. Уникальные обложки в едином стиле резко поднимают воспринимаемое качество. У каждого агента своя обложка + единая система типографики.

3. **OG-image для соцсетей** — превью ссылки при шеринге. Сейчас, скорее всего, дефолтный (если есть вообще). Прямо влияет на CTR в TG/VK когда лок-ин или кто-то делится ссылкой.

### Средний ROI

4. **«Как работает Hireon» — схема для лендинга** — 3-4 шага (выбрал агента → оплатил → ввёл API ключ → агент работает). Снимает базовое непонимание у новых посетителей.

5. **Карточка агента в каталоге `/agents`** — сейчас, вероятно, простая. Можно сделать с обложкой, бейджами категорий, ценой, рейтингом. Каталог-страница тоже конверсионная.

6. **Страница `/agents/[slug]`** — sales-page агента. Hero + описание + screenshots/демо + FAQ + CTA «Купить». Сейчас, наверное, минималка.

### Низкий ROI (можно если останется лимит)

7. **Empty states** — «у вас нет агентов», «каталог пуст под фильтр». Мелочь, но приятно.
8. **404 страница** — кастомная, под бренд.
9. **`/seller` лендинг** — для будущих продавцов, обновить после pivot'а на Gemini-модель.
10. **`/about` страница** — её, по-моему, ещё нет.

### Рекомендация

Если стоит выбор — начать с **#1 (hero) + #2 (обложки агентов)**. Это две вещи, которые видит первый пришедший на сайт пользователь. После них решать что дальше.
